# Issue and Card Template
 
    This issue and card template will help to make it harder to create a bad card. What is listed below should be included when making a card. Task Description, Estimate, Hat, and a Stopping Condition.

# Easy Paste into Card

    Task Description: (The task description lists what the card is made for and the steps that should be done to complete the card.)

    Estimate Time: ___ hours ___ minutes.

    Hat: (The hat is the role the student has taken on during the week they are in during the capstone.)

    Stopping Condition: (The stopping condition tells the developer what needs to be done in order to mark the card as done.)

# Full Card Example

    Task Description: Copy over the file: code/ai-usage-template.md into my repository as docs/ai-usage.md. Then fill in the policy header, after do a deliberate Amber-zone use and write the log entry with all six columns filled.

    Estimate Time: 45 minutes

    Hat: Project Manager

    Stopping Condition: The AI Usage file should have at least two entries with a Policy Header.


# Task Description:

    The task description lists what the card is made for and the steps that should be done to complete the card.
    
    Example of a task description: "Copy over the file: code/ai-usage-template.md into my repository as docs/ai-usage.md. Then fill in the policy header, after do a deliberate Amber-zone use and write the log entry with all six columns filled."


# Estimate: 

    The estimate is the estimated time it takes to complete the card list as such ___ hours ___ minutes.

    Example of a estimate time: 1 hours 15 minutes

    Note: Not all cards will take over an hour to complete, minutes maybe the only field necessary to have a good estimate.
    

# Hat: 

    The hat is the role the student has taken on during the week they are in during the capstone.

    Example of a hat: "Project Manager"

    Possible Hats that can be choosen for the card, with the week list listed for additional help:

    - Project Manager (Week 1)
    - Product Owner (Week 2)
    - Business Analyst (Weeks 3-4)
    - Architect (Weeks 5-6)
    - Project Manager (Week 7)
    - Architect, defending the design (Week 8)
    - Developer (Weeks 9-10)
    - Tester (Week 11)
    - Developer (Week 12)
    - Technical Writer (Week 13)
    - Developer, wearing the release-engineer hat (Week 14)
    - Product Owner (Week 15)
    - Project Manager (Week 16)


# Stopping Condition: 

    The stopping condition tells the developer what needs to be done in order to mark the card as done.

    Example of a stopping condition: "The AI Usage file should have at least two entries with a Policy Header."

    Note: The stopping condition should be descriptive enough to understand if that card is complete with only a yes or a no.
